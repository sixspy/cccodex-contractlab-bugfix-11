# 孤儿缓冲治理说明

> 锁定日期：2026-11-18。口径选定当天禁止改口；偏离本说明即拦下并记 `孤儿偏了` 事件。

## 缺陷现象

`buffers` 缓冲表出现不绑定真实批次的孤儿行（批次号为空或指向不存在的批次）：

- 缓冲队列查询用 `INNER JOIN ingress_batches`，孤儿行在页面队列中凭空消失，缓冲队列与入站列表对不齐；
- 对账接口对 `buffers` 直接 `COUNT(*)`，孤儿行被计入缓冲账册，`buffered` 与 `buffer_rows` 错位；
- 旧表仅有 `batch_id INTEGER NOT NULL`，无外键约束，连接也未启用 `PRAGMA foreign_keys`，数据库层无法拦截孤儿。

## 选定口径：甲路径（同事务双写 + 外键约束）

**本服务只走甲路径，不启用乙路径（隔离表），两边口径不得混用，禁止把孤儿支混入正式缓冲。**

1. `buffers.batch_id` 建外键 `REFERENCES ingress_batches(id) ON DELETE RESTRICT`，并对每个连接开启 `PRAGMA foreign_keys=ON`；无批次/空批号/不存在批次的缓冲插入由数据库直接拒绝。
2. 入站校验双写时，批次行与缓冲行在同一连接、同一事务内顺序插入；缓冲插入失败则整笔回滚，不留半截批次。
3. 历史孤儿行在启动迁移中登记 `governance_events` 后从 `buffers` 剔除（表重建迁移），不迁移进任何隔离表；运行期也可用 `POST /api/governance/sweep` 再次清扫。
4. 正式缓冲查询只认绑定真实批次的行，依赖外键保证，**不靠列表 WHERE 过滤兜底**；无批次缓冲一律不计入对账。
5. 清扫不得误删正式通过：任何与 `result='通过'` 批次关联的缓冲行，任何接口都拒绝删除并登记偏差。

## 并发口径

补齐（backfill）与清理（cleanup）两名值班同时抢写须排队：模块级写入门 `governance_gate` 串行化，后到者拿不到门即不执行写操作，只登记 `孤儿争用` 事件并返回 409。

## 范围约束

- 网页不另开：治理策略作为现有单页内的一个附页签，不新增路由、不新增页面文件。
- 会话沿用：继续使用内存 `SESSIONS` Bearer 令牌，不改动鉴权。
- 文件库不动：继续使用单机 SQLite `data/app.db`，不引入外置 Postgres 或其它存储。

## 接口与页面口径

缓冲队列（`/api/buffers`）、入站列表（`/api/ingress`）、缓冲详情（`/api/buffers/{id}`）、对账账册（`/api/reconcile`）、策略附页（`/api/governance/policy` 及前端附页签）均不得出现空批号：

- 外键保证写入侧不存在空批号；
- 对账新增 `orphan_rows` 单独披露孤儿数，`buffer_rows` 只数绑定真实批次的行，`aligned = (buffered == buffer_rows) AND orphan_rows == 0`。

## 偏差事件

所有偏离治理说明的操作在 `governance_events` 留痕，事件类型含：`孤儿迁移`、`孤儿清扫`、`外键拒绝`、`双写回滚`、`孤儿争用`、`孤儿偏了`。
